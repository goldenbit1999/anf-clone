## 환경

- 커널 `6.18.54.1-microsoft-standard-WSL2`, Ubuntu 24.04, `/etc/wsl.conf`에 `[boot] systemd=true`, PID 1은 systemd(`running`)
- WSL 메모리 7778 MiB, 스왑 2048 MiB. `/`는 ext4 `/dev/sdd` 1007G
- WSL `eth0` `172.21.163.178/20` (NAT 모드). Windows 쪽 게이트웨이 `172.21.160.1`
- Docker Desktop 27.3.1. 엔진도 같은 WSL 커널을 쓴다 (`docker info`: `KernelVersion=6.18.54.1-microsoft-standard-WSL2`, `OperatingSystem=Docker Desktop (containerized)`)
- 시험 시작 때 Docker Desktop의 Ubuntu 연동이 켜져 있었다. `/usr/bin/docker -> /mnt/wsl/docker-desktop/cli-tools/usr/bin/docker`, `/var/run/docker.sock`(group `docker`)를 Desktop이 만든다. 7번 전에 사용자가 연동을 껐다 (아래 "Docker Engine 설치")

## 설치한 패키지

```bash
apt-get install -y nfs-kernel-server btrfs-progs
```

`nfs-server`와 `rpcbind`가 `active`, `nfs-server`는 `enabled`(WSL 부팅 때 뜬다). `thin-provisioning-tools`, `lvm2`는 설치하지 않았다. S1(후보 C)에서 필요하다.

### Docker Engine 설치 (7번)

1. Docker Desktop → Settings → Resources → WSL integration에서 Ubuntu 토글을 끈다. 이것만으로는 풀리지 않는다. 기본 배포판인 Ubuntu는 **"Enable integration with my default WSL distro"**(기본값 켜짐)로 계속 연동되기 때문이다. 이 체크도 끄고 Apply & restart 한다. 결과: `settings-store.json`에 `"EnableIntegrationWithDefaultWslDistro": false`, `"IntegratedWslDistros": []`. Ubuntu에서 `/usr/bin/docker` 링크와 Desktop 프록시 프로세스가 사라진다.
2. 남은 `/var/run/docker.sock`(죽은 소켓 파일)을 지우고 `apt-get install -y docker.io`.
3. 결과: Docker Engine 29.1.3, `OperatingSystem=Ubuntu 24.04.1 LTS`, cgroup v2, overlayfs, `docker` 서비스 `active`·`enabled`. 사용자 `mkimhome1`은 이미 `docker` 그룹이라 root 없이 `docker`를 쓸 수 있다. Windows 쪽 Docker Desktop은 그대로 남아 있다.

## 설계에 주는 영향

- **D-06(storage agent)의 전제는 성립한다.** 커널 모듈, knfsd, 루프 파일 위 btrfs가 모두 이 환경에서 동작한다.
- **D-10(Docker 위치)은 Ubuntu 안 Docker Engine으로 정한다.** Docker Desktop은 마운트는 되지만(`insecure` 필요) 클라이언트 IP를 구분하지 못한다. 트래픽이 Windows를 돌아 들어오므로 처리량 측정(S2)에도 Windows NAT 경로가 끼어든다 [추론]. Ubuntu 안 Docker Engine은 브리지가 Ubuntu 네트워크에 있어서 ADR §5의 가정("Docker 네트워크 쪽 호스트 IP = 마운트 대상 IP")이 그대로 성립한다. 브리지 게이트웨이 `172.30.0.1`이 마운트 대상 IP 후보다.
- **export 옵션.** Docker Engine에서는 기본 `secure`로 된다. `insecure`는 쓰지 않는다.
- **Docker Desktop을 다시 Ubuntu에 연동하지 않는다.** 연동이 켜지면 `/usr/bin/docker`와 `/var/run/docker.sock`을 Desktop이 다시 차지한다.
- **NFSv3 잠금.** 클라이언트에서 `nolock`으로 마운트했다. 잠금(NLM)이 필요한 시험이 생기면 클라이언트 이미지에 `rpc.statd`를 띄운다.
- `exportfs`가 `/etc/exports`가 없다고 경고한다(`can't open /etc/exports for reading`). 동작에는 영향이 없다. agent는 `/etc/exports.d/`에 파일을 쓴다.

## 정리

Docker Desktop 시험과 Docker Engine 시험이 끝날 때마다 시험용 컨테이너(`s0-c1`, `s0-c2`), 네트워크 `anf-vnet`, export 파일, 루프 장치, `/var/lib/anf-clone/spike-s0`를 지웠다. 설치한 패키지(`nfs-kernel-server`, `btrfs-progs`, `docker.io`), `alpine:3.20` 이미지, 빈 `/var/lib/anf-clone`은 남겼다.

Docker Desktop 시험 뒤 정리할 때 `losetup -d /dev/loop0` 대신 `losetup -D`(모든 루프 장치 분리)를 썼다. Docker Desktop의 루프 장치 두 개(`loop1`, `loop2`, ISO 캐시)는 사용 중이라 분리되지 않았고 `AUTOCLEAR=1`로 표시된다. 이 값이 원래 설정(`mount -o loop`의 기본값)인지 이 명령 때문인지는 구분하지 못했다. 어느 쪽이든 Desktop이 마운트를 해제할 때 분리되는 것이라 정상 종료와 같다. 직후 `docker run --rm alpine:3.20 echo` 성공으로 Desktop 동작을 확인했다. 이후 스파이크와 agent는 자기가 만든 장치만 지정해서 분리한다. Docker Engine 시험 뒤에는 `losetup -d $(cat loopdev)`로 그 장치만 분리했다.
