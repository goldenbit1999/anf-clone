# test-automation 설계 (FR-10 테스트 자동화)

- 확정일: 2026-11-09 (`anf-roadmap` 총괄. 사용자에게 묻는 결정 없음, 아래 결정은 모두 `자동 채택`)
- 조사 브리프: 없음. PRD §8에서 FR-10은 조사를 생략한다 (ANF 기능이 아니다)

## 2. 지금 상태와 빈 곳

테스트 층은 이미 있다 (`backend/tests/unit` 13개 파일, `contract` 6개, `integration` 1개, `e2e` 16개 파일). 실제 커널 위의 마운트·스냅샷·처리량 시험도 기능 사이클마다 만들었고 각 사이클의 검증에서 통과했다. FR-10에서 비어 있는 것은 "자동화"다.

1. **데이터 플레인 묶음 전체를 한 번에 돌리는 명령이 없다.** 지금까지는 implementer와 verifier가 파일을 골라 손으로 돌렸고, 그때마다 환경 변수(`ANF_E2E_API_URL`, 로그 경로), `drop_caches`, VG 붙이기를 직접 챙겼다. 그 지식이 기록에만 있다.
2. **skip을 실패로 보는 검사가 CI 워크플로 안에만 있다** (`ci.yml`의 인라인 Python). 데이터 플레인 실행에는 없다.
3. **PRD 수락 기준과 테스트의 대응이 한곳에 없다.** 리뷰어가 "FR-05는 어떤 테스트가 증명하나"를 찾으려면 사이클별 보고서를 봐야 한다.
4. **일부 수락 기준은 verifier의 일회성 드라이버로만 확인했을 수 있다** (예: `_workspace/throughput-limit/verify/fr08_verify.py`). 묶음에 없는 기준이 있는지 확인된 적이 없다.

## 3. 범위

### 이번에 만든다

1. **데이터 플레인 테스트 실행기** `scripts/run-dataplane-tests.sh`: WSL에서 root로 명령 하나로 `dataplane` 마커 테스트(통합 + 데이터 플레인 e2e) 전체를 돌리고, 통과·실패·skip을 합쳐 종료 코드로 알린다 (§5).
2. **skip 검사 공용화**: JUnit XML을 읽어 "수집 0개, skip, 실패, 오류"를 실패로 판정하는 작은 Python 스크립트 하나를 두고, 실행기와 `ci.yml`이 같이 쓴다 (§5.3).
3. **수락 기준 ↔ 테스트 대응표** `docs/testing.md`: 테스트 층, 실행 명령, FR-01~FR-08 수락 기준마다 그것을 확인하는 pytest node ID (§6).
4. **빈 곳 채우기**: 대응표를 만들다 PRD §6.1의 수락 기준 문장 중 묶음의 자동 테스트가 없는 것이 나오면 e2e 테스트를 더한다. 제품 코드는 바꾸지 않는다.

### 이번에 만들지 않는다

- **CI의 data-plane 작업과 스파이크 S3**: FR-11이다. 이번 실행기는 그 작업이 부를 명령이 된다.
- **PRD §5 데모 대본 스크립트** (§9 성공 기준): 전체를 명령 하나로 띄우는 FR-13에서 만든다.
- **메트릭 테스트**(FR-12), 프론트엔드 테스트 변경(FR-09에서 끝남).
- **빠른 부분 묶음(smoke 마커)**: 필요한 곳이 아직 없다. FR-11이 러너 시간 때문에 필요하면 그때 정한다.
- **병렬 실행(pytest-xdist)**: 데이터 플레인은 기기에 하나고(VG, IP 대역, 포트 8080·8090) 처리량 시험은 다른 I/O와 겹치면 판정이 흔들린다.

## 5. 실행기 계약

### 5.1 명령

```bash
# Windows(Git Bash)에서
MSYS_NO_PATHCONV=1 wsl -d Ubuntu -u root -e bash /mnt/c/Users/mkimh/Projects/ANF-clone/scripts/run-dataplane-tests.sh
# WSL root 셸에서, 저장소 루트
scripts/run-dataplane-tests.sh [pytest에 넘길 경로·옵션...]
```

- 인자가 없으면 `backend/tests/integration`과 `backend/tests/e2e`에서 `dataplane` 마커가 붙은 테스트 파일 전부를 돌린다. 대상 파일은 목록을 스크립트에 적지 않고 수집 결과에서 얻는다(새 테스트 파일이 빠지지 않게).
- 인자로 파일을 주면 그 파일만 돌린다. `-k` 같은 pytest 옵션은 그대로 넘긴다.
- 환경 변수: `ANF_CLONE_VENV`(venv 위치), `ANF_TEST_OUT`(출력 폴더). 기존 e2e 변수(`ANF_E2E_USER` 등)는 그대로 통과한다. root로 돌면 `~`가 `/root`라서 `~/.venvs/anf-clone`을 그대로 쓸 수 없다. `ANF_CLONE_VENV`가 없을 때 venv를 찾는 방법은 구현에서 정하고 `docs/testing.md`에 적는다.

### 5.2 순서

1. 사전 점검(결정 7) → 실패면 원인을 출력하고 종료 코드 2.
2. VG 확인·붙이기(결정 8).
3. 기준선 기록(결정 10).
4. 대상 파일마다: `sync; echo 3 > /proc/sys/vm/drop_caches` → `python -m pytest <파일> -m dataplane --junitxml=<out>/<파일>.xml`을 `ANF_E2E_API_URL`, `ANF_E2E_LOG=<out>/<파일>.jsonl`과 함께 실행, 출력은 `<out>/<파일>.log`에도 남긴다. 파일별 소요 시간은 단조 시계로 잰다.
5. 남은 것 검사(결정 10).
6. `junit_gate.py`로 합산해 요약 표(파일, 통과, 실패, 오류, skip, 초)와 합계를 출력한다.

### 5.3 종료 코드

| 코드 | 뜻 |
| --- | --- |
| 0 | 수집 1개 이상, 전부 통과, skip 0, 남은 것 없음 |
| 1 | 실패·오류·skip이 있거나, 수집이 0개거나, 남은 것이 있거나, pytest가 죽어 XML이 없는 파일이 있다 |
| 2 | 사전 점검 실패. 테스트를 돌리지 않았다 |

`junit_gate.py`: 인자로 XML 파일 하나 이상을 받는다. 합계와 파일별 수를 출력하고, 위 1의 조건(남은 것 검사 제외)이면 1로 끝난다. `ci.yml`의 "Fail on skipped tests" 단계가 이것을 부른다(지금의 오류 문구와 뜻은 유지).

## 6. `docs/testing.md`

- 테스트 층 표(ADR §9.1을 실행 명령과 함께): 단위·계약(`python -m pytest -m "not dataplane"`), 컨트롤 플레인 e2e(`ANF_E2E_API_URL`), 데이터 플레인(실행기), 훅 테스트, 프론트엔드(`npm test`).
- 어디서 무엇이 도는지: Windows TDD 훅, WSL, CI. skip 규칙.
- 실행기 사용법, 출력 위치, 종료 코드, 전체 소요 시간(이번 실행의 실측).
- **대응표**: FR-01~FR-08 수락 기준 문장 → pytest node ID(파일::함수, 필요하면 매개변수 ID) → 클라이언트에서 관찰하는 것 한 줄.
- 알려진 한계: 클라이언트와 서버가 같은 커널(R-08), 처리량 판정은 게스트 단조 시계, 데이터 플레인 묶음은 아직 CI에서 돌지 않는다(FR-11).

`CLAUDE.md`의 Commands 절에 실행기 한 줄을 더한다(메인이 6단계에서).

## 8. 구현 중 변경

구현(feature-implementer, 2026-11-09)에서 정하거나 좁힌 것. 결정 1~13의 뜻은 바뀌지 않았다.

1. **VG 붙이기(결정 8)는 agent의 함수를 그대로 부른다.** 실행기가 venv Python으로 `FlexVolManager(Runner()).ensure_aggregate()`를 부른다. agent가 시작할 때(`recover`의 첫 단계) 부르는 함수라 절차가 같고, 이미지가 없으면 만드는 것까지 같다. agent를 잠깐 띄우는 방법은 버렸다: `recover`가 남은 볼륨의 인스턴스까지 띄워 기준선이 흔들린다. `losetup`·`vgchange`를 스크립트에 다시 쓰는 방법도 버렸다: 같은 절차가 두 곳에 생긴다. 제품 코드는 바뀌지 않는다.
2. **venv 찾기(§5.1).** `ANF_CLONE_VENV`가 없으면 저장소 주인(`stat -c %u`)의 `~/.venvs/anf-clone`을 쓴다. e2e 도우미가 anf-api 사용자를 venv 주인으로 고르는 것(`dataplane_live.e2e_user`)과 같은 사람을 가리킨다.
3. **남은 것 검사(결정 10)는 이름 접두사가 아니라 기준선과의 차이로 한다.** 통합 테스트는 볼륨 경로 `it-*`과 컨테이너 `it-client-*`를 써서 `e2ev*`·`anfe2e-cli-*`만 보면 놓친다. LV는 VG `anf`의 LV 이름(`vol_*`·`snap_*`) 전체, 컨테이너는 `docker ps -a` 전체를 실행 전과 비교한다. 다만 실행 전에 있던 볼륨(`vol_<uuid32>`)의 인스턴스 `anf-nfs-<uuid32>`는 세지 않는다. agent와 통합 테스트의 시작 복구가 그 인스턴스를 다시 띄우기 때문이다.
4. **시간.** 요약 표(§5.2 6)의 초는 JUnit XML의 `time`(pytest가 `perf_counter`로 잰 세션 시간, 단조 시계)이다. 실행기가 따로 재는 파일별·전체 시간은 `/proc/uptime`(단조)이고, 진행 줄과 `files.tsv`, `summary.txt`에 남긴다. bash의 `SECONDS`·`EPOCHREALTIME`은 벽시계라 쓰지 않았다.
5. **pytest 종료 코드도 본다.** XML이 깨끗해도 pytest가 0이 아닌 코드로 끝난 파일이 있으면 종료 코드 1이다. XML만으로는 내부 오류(pytest 종료 코드 3)를 놓칠 수 있다.
6. **`ANF_E2E_API_URL`은 설정돼 있지 않을 때만 기본값(`http://127.0.0.1:8080`)으로 채우고, 빈 값은 그대로 둔다** (`${ANF_E2E_API_URL-…}`). 일부러 빈 값을 주면 e2e가 skip하고 판정이 실패로 센다. AC-04 (b)를 그 방법으로 재현할 수 있다.
7. **실행 옵션.** 파일별 pytest에 `-v`(로그에 테스트마다 한 줄)와 `-p no:cacheprovider`, 환경 `PYTHONDONTWRITEBYTECODE=1`을 더한다. root가 Windows 체크아웃(`/mnt/c`)에 `.pytest_cache`·`__pycache__`를 남기지 않게 하는 것으로, 기존 e2e 실행 명령과 같다.
8. **경로 인자 구분(§5.1).** `-`로 시작하지 않고 `::` 앞부분이 실제로 있는 인자를 경로(파일, 폴더, node ID)로, 나머지를 pytest 옵션으로 본다. 값이 경로인 옵션은 `--deselect=<node ID>`처럼 `=`로 붙여 써야 한다(`docs/testing.md` §3).
9. **대응표 검사(결정 11)는 `pytest --collect-only`로 한다.** `test_testing_doc.py`가 표에 나온 파일을 수집해 node ID가 그대로 있는지 본다. 파일과 함수 이름만 보는 것보다 짧고 매개변수 ID까지 맞는다(AC-03이 쓰는 방법과 같다). FR-01~FR-08마다 테스트가 적힌 행이 있는지도 본다.
10. **빈 곳 채우기(§3의 4)는 할 것이 없었다.** PRD §6.1 FR-01~FR-08의 수락 기준 문장 23개가 모두 묶음의 자동 테스트(데이터 플레인 e2e, 통합, 컨트롤 플레인 e2e, 계약)에 대응해 e2e를 더하지 않았다. 표를 쓰며 남긴 것: 클론에는 `Canceled`로 끝나는 경로가 없다(FR-01). ARM 볼륨에는 한도가 없는 경우가 없어 FR-08의 "제한이 없는 볼륨"은 4,500 MiB/s 볼륨과 한도 없는 agent 볼륨(통합)이다.
