# Architecture: `backend/anf_api/`

- **Architecture (`backend/anf_api/`)**: `arm_app.py` is the FastAPI app (ARM routes, operation status URL, error format, correlation headers; the lifespan runs the worker). `accounts.py` holds the account body rules and PUT/PATCH/DELETE flows (account PATCH is synchronous). `capacity_pools.py` holds the pool body rules, throughput math (Auto limit formula, `utilizedThroughputMibps`, the Auto → Manual fill), parent/child and capacity checks, and PUT/PATCH/DELETE flows (pool PATCH is asynchronous). `volumes.py` holds the volume body rules, path and capacity checks, Manual QoS rules and the pool throughput budget, flows (including the revert action and creating a volume from a snapshot), and the handlers that call the agent, record `mountTargets` (and, for a restored volume, `originatingResourceId` and the base snapshot row), and delete snapshot rows the agent no longer has (after a revert, and after a volume ensure that finished one). `snapshots.py` holds the snapshot body rules (no writable properties, no tags, so no PATCH), parent-state and 255-per-volume checks, flows (a re-PUT is an async UPDATE that re-ensures the agent snapshot; a source snapshot of a volume still being restored cannot be deleted), and the handlers that record `created`. `storage_client.py` calls the agent (urllib in a thread, 60 s connection retry, job polling, re-send when a job is gone; `revert_volume` and `snapshot_uuids` for the revert, `ensure_volume(clone=)` and `snapshot_records` for restoring to a new volume). `lro.py` is the shared LRO worker (asyncio, same process, D-09), fault injection (keys come from the registered handlers, e.g. `capacityPools/patch`), and operation status body. `state_store.py` is SQLite (`resources`, `operations`; one active operation per resource; `Tx.ensure_no_children` for nested-resource 409s; `Tx.delete_resource` also deletes child rows, so a volume DELETE removes its snapshots). `api_metrics.py` holds the Prometheus metrics (request middleware by route template, operation counters, duration histograms, in-progress gauge) that `arm_app.py` and `lro.py` update, served at `GET /metrics`. `arm_rules.py` covers api-version, name rules, resource IDs, `ArmError`, and shared error builders. A write stores the resource state and the operation in one transaction, responds, and the worker finishes the operation; on restart it re-runs unfinished operations.
