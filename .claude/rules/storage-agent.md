# Architecture: `backend/storage_agent/`

- **Architecture (`backend/storage_agent/`)**: a root process serving an ONTAP REST subset (`agent_app.py`: `/api/storage/volumes` including FlexClone `clone` fields and `qos.policy.max_throughput_mbps` on POST and the restore `PATCH`, `/api/storage/volumes/{uuid}/snapshots`, `/api/cluster/jobs`, input re-checks). `flexvol.py` turns a volume into a thin LV + ext4 mount under `ns/<creationToken>` and keeps path, uuid, IP, protocol, and throughput limit (`anf_qos`) in LVM tags (no DB); a snapshot is a read-only thin snapshot LV `snap_<uuid32>` with its own tags, mounted under `.snapshot/<name>`; `restore` swaps the volume LV and records progress in tags (`anf_rv_req`, `anf_rv_snap`, `anf_rv_new`, `anf_rv_done`); `create` with a clone parent makes the volume from a snapshot and records progress in `anf_cl_*` tags. `nfs_instance.py` runs one `anf-nfs-server` container per volume (`nfs_server/` holds its Dockerfile and entrypoint), writes its export table under `/var/lib/anf-clone/exports/<uuid>` and applies it with `exportfs -ra`, applies the volume's throughput limit in the instance netns between start and readiness, waits up to 150 s for the instance to be ready, and blocks/unblocks an instance's netns input for the revert window; `check_host` also requires `fs.leases-enable = 0`. `volume_metrics.py` is the scrape-time collector behind the agent's `GET /metrics` (knfsd stats per instance pid found through the Docker API socket, `statvfs`, and `FlexVolManager.inventory()` / `aggregate_usage()`); a volume that cannot be read does not hide the others, and a scrape does not wait for a running job. `jobs.py` is the in-memory job table (one job at a time). `runner.py` runs commands without a shell. Every step checks real state first, so repeating a request resumes it.
